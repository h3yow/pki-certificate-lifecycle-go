# 本地证书签发与生命周期管理（Go）

一个零外部依赖、可本地运行的私有签发方（CA）与受管实体模拟组件。它使用本地
P-256 ECDSA 密钥材料与本地 JSON 状态文件，提供**签发、信任链校验、密钥轮换、
吊销**能力。所有状态变更都串行化、原子持久化，保证在并发交织与进程重启后结论
一致、可解释、可复现。

- 语言/工程约定：Go 1.25，标准库 `crypto/x509`、`crypto/ecdsa`；单包 `pki`，
  命令行示例在 `cmd/pki-demo`。
- 无网络、无外部 CA、无第三方 Go 依赖。

## 快速开始

```bash
# 端到端演示：引导 -> 注册 -> 签发 -> 校验 -> 轮换签发方 -> 吊销 -> 再校验
go run ./cmd/pki-demo -state /tmp/pki-demo.json

# 全量测试（含竞态检测）
go test ./... -race -count=1 -v
```

## 核心类型与入口

| 入口 | 作用 |
| --- | --- |
| `NewManager(store)` | 加载持久化状态或引导全新签发方；状态损坏/版本过新时直接拒绝启动 |
| `RegisterEntity(name, allowed)` | 注册受管实体及其**允许申请**的用途集合 |
| `RotateEntityKey(name)` | 轮换实体密钥；旧证书仍可校验，之后签发使用新密钥 |
| `Issue(IssueRequest)` | 按请求约束签发并持久化证书，返回序列号与有效期 |
| `Verify(certDER, required)` | 在当前时钟下校验，返回带“判定依据”的 `VerifyResult` |
| `RotateIssuer()` | 创建新一代签发方并原子切换；旧代次继续受信 |
| `Revoke(serial, reason)` | 追加不可回退的吊销记录 |
| `IsRevoked(serial)` / `IssuedSerial(serial)` | 吊销/签发记录查询 |

`Clock` 接口可注入固定时钟（`frozenClock` / 测试中的 `mutableClock`），令过期、
未生效等结论完全可复现。

## 签发规则

`IssueRequest` 的每一项都按请求约束严格生效，**不会用默认值兜底**：

- `Entity`：必须满足确定性标识文法（见下），且必须已注册，否则分别返回
  `ErrInvalidIdentity` 与 `ErrIdentityNotFound`。
- `Usages`：非空、只能含已知位，并且必须是该实体 `allowed` 的子集。
  - 空集合 / 含未知位 / 超出实体允许范围 → `ErrUsageConflict`。
- `TTL`：必须 `> 0` 且 `<= MaxTTL`（一年）。
  - `TTL == 0` **不会**被当成默认时长，返回 `ErrTTLOutOfRange`。
- `SerialNumber`：`0` 表示由签发方分配单调递增序列号；显式提供正数时必须唯一，
  重复返回 `ErrSerialDuplicate`；负数返回 `ErrSerialOutOfRange`。
  - 自动分配计数器始终严格高于历史最高序列号（包括显式指定值），因此并发签发
    与“先指定高位号再自动分配”都不会产生重复号。
- `NotBefore`：零值表示“当前时刻”；显式提供未来时刻会签发“尚未生效”的证书，
  不会被静默改为当前时间。

### 标识文法

一个或多个以 `.` 分隔的 DNS 标签段；每段 1–63 字符，字符集 `[a-z0-9-]`，且段首
段尾必须是字母或数字。空串、大写字母、空格、下划线、前导/末尾连字符、连续点、
非 UTF-8 等一律拒绝。

### 密钥用途位

`DigitalSignature`、`KeyEncipherment`、`ClientAuth`、`ServerAuth`，映射到 X.509
`KeyUsage` / `ExtKeyUsage`。未知位（掩码之外）的请求一律拒绝。

## 校验规则与可区分结论

`Verify` 不返回布尔而是返回 `VerifyResult{OK, Reason, Basis, ...}`，失败结论互不
相同、绝不静默通过。固定判定顺序（先到先判，便于解释）：

1. **信任域与签名**：证书签发者 CN 编码 `域ID + 代次`。
   - 域 ID 不匹配（另一个独立引导的 PKI，即便代次号相同）→ `ErrUntrustedIssuer`。
   - 代次不在受信集合 → `ErrUntrustedIssuer`。
   - 域与代次正确但签名验证失败 → `ErrSignatureInvalid`。
   - 输入无法解析为 DER 证书 → `ErrMalformedCertificate`。
2. **时间窗口**：
   - `now < NotBefore` → `ErrCertificateNotYetValid`（尚未生效）。
   - `now > NotAfter` → `ErrCertificateExpired`（已过期）。
3. **吊销**：本地吊销表为权威状态，命中 → `ErrRevoked`。
   - 证书通过了信任与签名校验但本地无对应签发记录（序列号未知）→
     `ErrCertificateNotFound`，不会被当作有效证书。
4. **用途**：证书用途不含所要求的单个已知位 → `ErrUsageMismatch`。

`required` 必须是**单个**已知用途位；传 0、多位或未知位返回 `ErrUsageConflict`。
`Basis` 字段以人类可读方式给出判定依据（当前时刻、有效期窗口、域 ID、用途掩码、
吊销时间等），单测会打印输入、依据与最终结论。

## 轮换语义

### 签发方轮换（`RotateIssuer`）

- 每次轮换生成新密钥与新一代自签 CA；新旧信任材料**并存**：所有历史代次都保留在
  受信集合中，因此历史证书按“其签发时刻活跃的信任关系”继续校验通过。
- 切换**原子可见**：内存变更先暂存，只有整份快照 `Save` 成功后新代次才激活。
- **中途失败不留孤儿**：若持久化失败，内存状态精确回滚到切换前，旧签发方仍活跃，
  不会出现“既不被旧信任、也不被新信任接受”的证书。
- 崩溃角落：若在“新代次材料已落盘、激活指针未更新”之间中断，重启恢复逻辑会保留
  该代次为受信（它未签发过任何证书），活跃代次不变，并把高水位推进到该号，下次轮换
  不会重号。
- 每个信任域在引导时生成随机 16 字节**域 ID**；同一域的所有代次共享该 ID，独立引导
  的两个 PKI 域 ID 不同，避免“代次号相同即误信”。

### 实体密钥轮换（`RotateEntityKey`）

- 为已注册实体生成新密钥并原子持久化；轮换前签发的证书仍正常校验，之后的签发绑定
  新公钥。未知实体返回 `ErrIdentityNotFound`。

## 吊销语义

- 吊销是**只增、不可回退**的结论：一旦持久化，对之后所有 `Verify` 立即可见，重启后
  不丢失。
- 重复吊销 → `ErrAlreadyRevoked`；吊销不存在的序列号 →
  `ErrCertificateNotFound`；两者与成功吊销可区分。
- `IsRevoked` 对未知序列号返回 `ErrCertificateNotFound`，不会静默回答 `false`。

## 并发与持久化一致性

- `Manager` 内部单一 `sync.RWMutex`：签发、轮换、吊销等写操作完全串行，校验使用读
  锁但与写操作互斥，杜绝重复序列号与半更新状态。
- 存储采用“临时文件 + fsync + 同目录 rename”原子替换，任何时刻磁盘上要么是旧快照、
  要么是完整新快照，不会读到半截文件。
- 变更流程：持锁 → 编码旧快照 → 改内存 → 编码并原子 `Save` → 失败则用旧快照回滚。
  对外确认（函数成功返回）的签发/吊销必然已落盘。

## 本地状态格式与兼容范围

状态为单个 JSON 文件（默认权限 0600），顶层 `formatVersion` 标识格式版本：

- 当前写出 **v1**。
- **读取兼容**：接受 `formatVersion` 缺失（按 0 处理，等同 v1 布局）与 v1；缺失字段
  语义确定稳定——空切片即空集合，计数器零值表示“从 1 开始”。
- **版本过新拒绝**：`formatVersion > 1` 返回 `ErrStateVersionUnsupported`，绝不按
  不确定状态继续服务。
- **损坏拒绝**：非法 JSON、半截写入、序列号非正/重复、记录缺证书或实体、有效期窗口
  非法、吊销指向不存在的证书、签发者缺密钥/证书/域 ID、同域代次域 ID 不一致、
  `nextSerial` 不高于已用最大号等，均返回 `ErrStateCorrupt`。

字段缺失不会被静默错列或丢弃：要么有确定的零值语义（空集合/起始计数），要么直接判
定损坏并拒绝启动。

## 验证方法

```bash
go build ./...
go vet ./...
go test ./... -race -count=1          # 竞态检测
go test ./... -race -count=1 -v       # 查看每个用例的输入/判定依据/结论
```

覆盖场景（见 `pki/*_test.go`）：

- 标识非法、TTL 越界、用途冲突、序列号重复/越界等拒绝原因可区分；
- 过期、尚未生效、签发方不受信（外域）、签名被篡改、用途不匹配、已吊销等校验结论
  两两可区分，且失败不静默通过；
- 吊销后校验、重复吊销、吊销不存在证书；
- 固定/显式序列号重复、60 路并发签发唯序列号、签发/校验/轮换并发交织；
- 轮换与签发中途存储失败的回滚、已落盘未激活签发者的崩溃恢复、重启后签发与吊销结论
  不丢失；
- 状态损坏、半截文件、未来格式版本的明确拒绝。
